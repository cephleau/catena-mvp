## Submission Rules

**For new website form submissions:**

1. ✅ **Always send:**
   - `Name` (title) — auto-generated
   - `Language` (rich_text) — from form
   - `Modality` (select) — from form
   - `Requested Start` (date) — from form
   - `Workflow Status` (status) — always "New"

2. ✅ **Send if provided:**
   - `Service Type` (select) — if specialty given
   - `Priority` (select) — if priority specified
   - `Expected Duration (min)` (number) — if duration given
   - `Connection / Location` (rich_text) — if organization given

3. ❌ **NEVER send from form:**
   - `Actual Start`, `Actual End`
   - `Scheduler`, `Interpreter`, `Client` (unless IDs are resolved)
   - `Workflow Status` (preset to "New", not user input)
   - `Interpreter Response`, `Outcome`
   - `Completion Evidence`, `Cancellation / No-show Reason`
   - `Billing Ready`, `Payment Ready` (allow defaults)
   - `Request ID` (Notion auto-generates)

## Error Handling

- **Invalid select value:** Return user-friendly error ("Please select a valid option")
- **Notion API error:** Log internally; never expose to user
- **Missing required field:** Return validation error before API call
- **Relation field without valid ID:** Skip the field; do not send invalid references

## API Adapter Responsibilities

1. Map form fields to Notion properties (user-friendly → canonical)
2. Validate all select values against Notion database options
3. Sanitize all text inputs (HTML entity escaping)
4. Set `Workflow Status` to "New"
5. Only send populated, non-internal fields
6. Handle Notion API errors gracefully
7. Never expose Notion errors or internal structure to frontend
